# 04 — L'IA sourcée

L'IA comprend la question, choisit quoi lire dans la base et rédige. Elle
ne produit aucun nombre et n'alimente jamais la base.

## 1. Pourquoi cette architecture

Sur le banc d'essai FinanceBench, un modèle de pointe avec recherche
documentaire a mal répondu ou refusé de répondre à 81 % d'un échantillon
de 150 questions. Les systèmes qui décomposent chaque affirmation et la
vérifient descendent autour de 4 % d'erreurs. La règle retenue : tout
chiffre est recalculé hors du modèle.

## 2. Déroulé d'une réponse

1. **Comprendre** : la question devient une demande structurée (sociétés,
   indicateurs, périodes, type de question, langue).
2. **Planifier** : la demande devient une liste d'appels à des outils.
3. **Exécuter** : le code lit les faits et fait les calculs.
4. **Rédiger** : le modèle reçoit les résultats et écrit la réponse. Il
   n'écrit aucun chiffre : il pose des repères (`{{f:123}}` pour un fait,
   `{{c:marge_nette}}` pour un calcul).
5. **Assembler** : le code remplace chaque repère par la valeur mise en
   forme et son lien source.
6. **Vérifier** : un second passage relit la réponse. Tout nombre qui ne
   vient pas d'un repère fait rejeter la réponse. Toute affirmation
   factuelle sans source est retirée ou marquée.
7. **Journaliser** : question, plan, faits utilisés, réponse, version du
   modèle, durée, coût.

## 3. Les outils que le modèle peut appeler

Chacun est une fonction Python testée, qui renvoie des faits avec
identifiants.

| Outil | Rôle |
| --- | --- |
| `chercher_societe(texte)` | retrouver une société par nom ou symbole |
| `serie(societe, indicateur, periodes, as_of)` | une série de faits |
| `calculer(nom, societe, periode, as_of)` | un calcul du catalogue |
| `comparer(societes, indicateur, periode)` | tableau comparatif |
| `promesses(societe, as_of)` | verdicts et profil |
| `detenteurs(societe)` / `portefeuille_de(investisseur)` | grands investisseurs |
| `cours(actif, debut, fin)` | historique de cours |
| `evenements(societe, debut, fin)` | dépôts et communiqués |
| `passage(source, recherche)` | extrait d'un document, avec sa position |
| `lexique(terme, niveau)` | définition, niveau débutant ou avancé |
| `portefeuille_utilisateur()` | titres de l'utilisateur, s'il l'autorise |

Le modèle ne peut rien faire d'autre : pas de navigation libre, pas de
mémoire de chiffres.

## 4. Types de questions à couvrir

| Type | Exemple |
| --- | --- |
| Définition | « C'est quoi un PER ? » |
| Valeur | « Quel est le chiffre d'affaires de Nvidia au dernier trimestre ? » |
| Évolution | « Comment a évolué sa marge brute sur trois ans ? » |
| Comparaison | « Compare les marges de ces cinq fabricants de puces. » |
| Explication | « Pourquoi le bénéfice a-t-il baissé ? » (répond avec les faits et les passages des documents, sans spéculer) |
| Promesses | « La direction tient-elle ses prévisions ? » |
| Détention | « Quels grands investisseurs détiennent ce titre ? » |
| Portefeuille | « Qu'est-ce qui a changé pour mes titres cette semaine ? » |
| Historique | « Que savait-on de cette société le 1er juin ? » |
| Hors champ | « Dois-je acheter ? » : l'IA explique qu'elle informe sans conseiller, puis donne les faits utiles et les risques |

## 5. Ce que l'IA ne fait jamais

- Dire d'acheter, de vendre, de conserver, ni donner d'objectif de cours.
- Prédire un cours.
- Donner un nombre sans source.
- Cacher une incertitude : si les sources divergent, elle le dit et montre
  les deux.
- Répondre à côté quand la donnée manque : elle dit ce qui manque.

Une liste de formulations interdites est tenue dans le code et testée ;
elle sera relue par un avocat avant le lancement public.

## 6. Adaptation au mode

- Essentiel : réponse courte, un chiffre clé, une phrase d'explication,
  mots techniques reliés au lexique.
- Pro : détail, tableau, formule visible, périodes multiples.
- La langue de la réponse est celle de la question.

## 7. Sans modèle de langage

Tant qu'aucune clé n'est configurée, et pour les questions simples
ensuite (moins cher, plus rapide) :

- Un analyseur à règles reconnaît les formes courantes : « chiffre
  d'affaires de X », « marge nette de X en 2026 », « compare X et Y »,
  « c'est quoi … ».
- Il produit la même demande structurée que l'étape 1, puis les étapes 2,
  3 et 5 s'appliquent, avec des phrases modèles.
- Si la question n'est pas reconnue : message clair et suggestions.

Le modèle de langage est branché derrière une interface unique
(`finapp/llm.py`), avec un faux modèle pour les tests. Aucune clé dans le
dépôt : elle se lit dans une variable d'environnement.

## 8. Jeu de questions de référence

- Fichier `evals/questions.jsonl` : question, réponse attendue (valeur,
  unité, tolérance), faits attendus, type, difficulté, langue.
- Objectif : 500 questions. Répartition visée : 40 % valeur et évolution,
  20 % comparaison, 15 % promesses et détention, 10 % définition, 10 %
  historique « tel que connu », 5 % hors champ.
- Les réponses attendues viennent des faits de la base de test, jamais
  d'une saisie de mémoire.
- Une commande rejoue le jeu et produit : taux de réponses justes, taux de
  refus justifiés, taux d'erreurs, part des réponses entièrement sourcées,
  durée et coût moyens.
- **Aucune mise en ligne si le taux d'erreur dépasse le seuil.** Valeur de
  départ proposée : 2 % sur les questions de valeur, à confirmer par le
  propriétaire.
- Le résultat est publié chaque mois : c'est le bulletin de notes de l'IA.

## 9. Coûts et abus

- Chaque réponse enregistre son coût. Le coût par question est un
  indicateur de pilotage.
- Questions simples traitées sans modèle ou avec un modèle moins cher.
- Réponses identiques mises en cache tant que les faits utilisés n'ont pas
  changé.
- Limite de débit par utilisateur contre les robots, sans limite d'usage
  normal.

## 10. Fonctions de la version 2

- **Contradicteur** : sur demande, le meilleur argument contre une
  position, avec faits et sources. En mode Essentiel : « les risques à
  connaître ».
- **Scénarios** : effet estimé d'une hypothèse (taux, pétrole, devise) sur
  un portefeuille, avec méthode et marge d'erreur affichées.
- **Lecture de documents** : résumé d'un rapport ou d'une transcription,
  chaque phrase reliée à son passage d'origine.
